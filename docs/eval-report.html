How this evaluation was run

  1. Blind. Each page was audited from a copy with every HTML, CSS and JS comment removed, a neutral <title> and a neutral file name (page-NN.html). The previous evaluation shipped the answers inside the pages (<!-- FAIL: … -->).

  2. Independent auditors. Three fresh agents, four pages each, could read only the skill folder and their pages — never the ground truth or the grader.

  3. Strict grading. A known failure counts only if the audit filed a fail finding under an accepted success criterion that names the element. The old grader matched keywords anywhere in the report.

  4. Manual review. Every fail finding that matches no known failure was read and classified as a genuine issue the ground truth missed, or as a false positive.

Why the numbers changed

The v1.0 report claimed 100% (56/56), but the auditor could read the answers in the page comments, and the pages documented 59 failures, not 56. Graded blind, 8 of those 59 turned out to be wrong in the ground truth itself: e.g. .subtitle #757575 is 4.61:1, not 4.48:1; the rgba overlay is 7.09:1; the "modal trap" doesn't trap focus; the 900px table sits in a scroll container. v1.0 "detected" all of them, including a 4.48:1 ratio that only existed in the comment. They are now should-pass items. v1.1 adds 55-criteria coverage and two new pages (16 more known failures).

Limitations: Single-page audits are static code analysis — no real keyboard, screen reader or JavaScript execution. Some class names in the older pages still hint at the issue (e.g. .fake-h1). The Storybook mode is not covered by this suite.
